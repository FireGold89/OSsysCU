香港中小型工程公司 · QS 工作流程

Mepork Engineering · OSsysCU 模組對照 · 編製日期：2026-08-31

適用：主判（M）、分判（SC）、物料／其他（M/O）之中小型承建商 QS 部門

1. 項目生命週期（總覽）

投標／判給→ 開工與判項建立→ 期中糧款 IP→ 實質完工 PC→ 主合約 FAC→ 分判 FAC→ DLP 保修期→ Retention 釋放

中小型公司 QS 通常一人多職：主合約糧款、分判付款、FAC 總表匯報並行。Excel（Final Account Status List）常作對外／對管理層匯報；系統作付款與結算工作底稿。

5. 最終結算（Final Account, FAC）

FAC 分兩條線，時間上常交錯，非一次完成。

5A. 主合約 FAC（對 Client）

  1. QS 編製 Statement of Final Account（A–K）
  2. 與 Architect／Client 修訂 VO、Retention、LAD
  3. 雙方簽署 → 記 MP FAC Signed Date
  4. 總表 Client FA：進行中 → 待簽 → 已完成

匯報狀態client_fac_statusN 項目結算總表

5B. 分判 FAC（對每個 SC，逐判獨立）

  1. 按判項出 SC Statement（原合約 + VO − 代支 − 已付 = 尾款）
  2. 分判商確認、簽回
  3. 付尾款（Final Payment IP）
  4. 總表該判 → 已完成
「待簽」實務定義（QS Excel）：帳目上糧款已結清或尾數極小，但簽署版 FAC 尚未收回（或尚未完成 OA）。屬 QS 業務判斷，非系統自動從單一付款欄位推定。
狀態意思資料來源（現況）
已完成 FAC 已簽、該判結案 Excel 匯入 總表手選；規劃：每判簽署日
進行中 尚有尾數或 FAC 進行中 Excel／手填；可對照分判 FAC outstanding
待簽 餘款≈0 但未簽 Excel／手填（例：N27 SC-004 判2）

9. 簽署記錄 — 建議處理方式（規劃）

層級應記錄現況建議
Client（主合約） mp_fac_signed_date + FAC／PC／MG 附件 ✅ 已有 推 Client FA「已完成」
每個 SC（如 SC-004） 該判簽署日 + 已簽 PDF ❌ 僅項目級 sc_fac_signed_date，粒度不足 加於 subcontractors 或分判 FAC 頁
N 項目結算總表 匯報狀態 Excel／手填 有簽署日時「建議已完成」，不強制覆寫

分判 FAC 狀態推導規則（規劃，空槽或未手填時）

狀態推導條件
已完成該判 fac_signed_date 有值，或已簽 PDF 已存
待簽outstanding ≈ 0（修訂合約 − 已付 − 扣款），但未簽
進行中有分判，且 0 < 已付 < 修訂合約
—無此分判

outstanding 計算與「分判最終結算」頁相同（sc_fac.py：原合約 + VO − 已付 − 代支）。
